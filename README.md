# Z.T.L

Z.T.L 是一个给个人使用的桌面副手。它把时间、天气、邮件、日程、纸条、书签和秘密放在一个 Qt 应用里，帮助你减少在多个工具之间切换。

项目只服务一个使用者。邮箱、API Key、云服务器、模型账号和端口都由使用者自己填写。程序数据统一放在安装目录旁的 `data/` 中，安装位置固定在 D 盘。当前源码、脚本和测试组成一个可直接构建的 Windows Qt 项目。

## 当前版本

当前版本已完成阶段一、二及阶段三的 Calendar 扩展，随后增加个人云端同步、后台邮件与天气缓存。前两阶段见 [阶段一、二开发报告](report-phase1-phase2.md)，Calendar 初版见 [开发报告](report-phase3-calendar.md)，后续修复与验收见 [Calendar 稳定性报告](report-calendar-robustness.md) 和 [界面调整报告](report-calendar-layout.md)。当前包含：

- Home：本地时间、天气、动态背景、今日全天标签、进行中的区间事务、今日和明日 DDL、未读邮件摘要。
- Mail：多账号 IMAP 同步、邮件列表、正文按需获取、搜索、收藏、本地删除与恢复。
- Calendar：DDL、全天标签、同日区间事务，日程节点高亮、历史周/月操作、类别筛选和周空闲时间压缩。
- Note：纸条、网站/文件/文件夹书签、加密秘密、备份、恢复、主密码和恢复草稿。
- 设置：天气、邮件、Calendar、Note、独立标签组、开机启动、托盘行为和数据目录。
- 云端：单用户 HTTPS 服务、离线同步队列、冲突选择、后台 IMAP 轮询、天气缓存及自动备份；详见 [使用与运维](docs/cloud/使用与运维.md)。
- 测试：vault、note、core、UI、邮件同步和 Python 邮件适配器测试。

详细使用方法见 [instruct.md](instruct.md)，v2.0 需求原文见 [require.md](require.md)，开发前的 v1.0 需求评估见 [report.md](report.md)，当前实现与已确认规则见合并阶段报告。

## v2.0 目标

v2.0 交付四条主线：

1. 把 DDL 扩展成以 Calendar 为中心的日历系统。
2. 增加个人自托管云端，让 Z.T.L 可以在设备关闭时继续执行联网任务。
3. 接入模型接口，让模型通过受控命令处理日程和今日清单。
4. 用统一的界面规范和动效重做前端体验。

开发按三个阶段推进。每个阶段结束后先验证本阶段的可用闭环，再进入下一阶段。

## 开发路线

### 阶段一：现有 bug 修复和优化

阶段目标：让当前版本稳定、可恢复、可卸载，并清理 v1.0 使用中已经确认的问题。

#### 窗口、托盘和隐私

- 保存并恢复窗口位置、大小、最大化和全屏状态。
- 窗口关闭到托盘后，托盘再次打开时回到 Home。
- 统一弹窗规则：错误和确认框保留到用户处理，普通弹窗在 Z.T.L 内点击其他位置时收回。
- 只有秘密窗口在 Z.T.L 失焦、系统锁屏、闲置超时、切换页面或显式锁定时关闭。
- 把托盘菜单“关闭秘密卡片”改成“立即锁定秘密”，并保留保存失败时的加密恢复草稿。
- 增加开机自启动开关。自启动后进入托盘，不抢占当前窗口焦点。

#### 数据路径和部署

- 生产环境的数据根目录固定为 exe 同目录的 `data/`。
- `data/` 包含配置、SQLite、密库、日志、缓存、同步状态、备份、临时文件、崩溃日志和更新缓存。
- Python 运行时、Qt 依赖和邮件脚本继续放在安装目录中，程序产生的临时内容也写入安装目录下的 `data/`。
- 开发测试继续允许 `ZTL_DATA_DIR`、`ZTL_SCRIPTS_DIR`、`ZTL_PYTHON` 覆盖路径；正常运行不写入 C 盘的用户数据目录。
- 部署包提供清晰的目录结构，卸载时由使用者选择是否删除 `data/`。

目标目录：

```text
D:\ZTL\
├── Z.T.L.exe
├── data\
│   ├── config\
│   ├── database\
│   ├── cache\
│   ├── logs\
│   ├── tmp\
│   ├── crash\
│   ├── update-cache\
│   └── vault.ztlvault
├── runtime\
└── scripts\
```

#### Mail、Note 和书签

- IMAP 同步保存摘要后，立即把本批邮件标记为服务器已读。
- 邮箱账号名称允许中文，邮箱地址仍作为账号稳定标识。
- 文件书签提供“打开文件”和“在资源管理器中定位”两个动作。
- 文件夹书签直接打开目标文件夹，不再通过父目录定位。
- 修复路径包含中文、空格、网络盘和目标已移动时的错误提示。
- Note 卡片增加长按拖动排序的基础能力，并持久化排序字段。

#### Calendar 基础整理

- 用户界面统一使用 `Z.T.L` 作为软件名。
- DDL 页面改名为 Calendar，使用 `Alt+C`，移除 `Alt+D`。
- Calendar、Mail、Note、设置页面增加统一的左上角页面标题。
- DDL 和 Note 拆分为两套标签组。
- 标签支持中文，统一按“中文 2、英文 1”的加权长度规则校验，默认上限为 10。
- 标签校验禁止逗号、换行、控制字符和空标签。

#### 阶段一交付与验收

- 新安装包在 D 盘运行后，所有用户数据都出现在 exe 同目录 `data/`。
- 关闭到托盘、再次打开、重启程序后，窗口状态和 Home 入口符合预期。
- 应用失焦只关闭秘密窗口，不关闭普通编辑窗口。
- 邮件同步完成后，服务器对应摘要带有已读标志。
- 文件、文件夹、中文标签和卡片排序通过 UI 测试。
- 构建、单元测试、邮件适配器测试和部署脚本全部通过。

### 阶段二：简单功能扩展

本阶段按 [require-phase2.md](require-phase2.md) 和本轮确认的规则实现，记录见 [阶段一、二开发报告](report-phase1-phase2.md)。

- Calendar、Note、Mail 使用高级筛选弹窗，取代原有快捷搜索和标签控件。多个标题关键词和标签须全部匹配。
- Calendar 支持标星与可选日期范围；指定范围时展开其中全部匹配循环实例。大量结果分批绘制。
- 循环编辑器启用后必须填写正整数剩余次数。每天显示说明，每周用一排七个按钮选择星期，每月用五行七列按钮选择日号，选中时整块点亮。截止时间经过、提前完成或删除本次都会消耗一次，不重复扣减。
- 网站书签保存默认浏览器、Edge 或 Chrome 的选择。找不到指定浏览器时使用系统默认浏览器；找到后启动失败则提示原因。
- Note 按住约 450 毫秒进入拖动时，卡片上边亮起，拖动结束后恢复。
- Mail 支持多个收信账号、日期范围、已读状态和收藏状态，先筛选再分页。
- 设置按 Home、Mail、Calendar、Note、Advance 排列；各项用途见阶段报告。

本阶段保留阶段一的安装目录内存储、普通编辑草稿、秘密锁定、邮件同步即标记服务器已读、分类内排序等行为。全天标签、区间事务，以及模型、云端和前端整体升级放在后续阶段。

### 阶段三：高级功能实现

阶段目标：完成 v2.0 的四条核心主线。阶段三按 Calendar、云端、模型、前端四条子线并行设计，先做可用闭环，再扩展细节。

#### Calendar 三种类别（已实现）

本轮以 [require-phase3-calendar.md](require-phase3-calendar.md) 和确认后的规则为准，修改均在 `v2.0-phase3-calendar` 分支。

- **DDL**：保留标题、描述、标签、截止时间、有限循环、标星、完成和提醒。日程单击选择、双击详情；完成按钮独立操作。已完成且过期的记录保留在历史周、月视图中，日程隐藏。
- **全天标签**：日期、标签内容和描述，同日可添加多个。显示在日程日期下方、周日期栏、月日期旁，以及 Home 日期下方；不参与待办、完成、提醒或高级筛选。
- **区间事务**：标题、描述、标签、开始与结束时间、有限循环和标星。必须同日且开始早于结束，允许重叠。日程和周视图显示开始、结束两个节点；悬停或选择时高亮覆盖时间段。结束后从日程隐藏，历史周、月仍可查看、编辑、删除。没有完成或提醒操作。
- 新增表单按类别切换字段，编辑时固定类别。高级筛选可多选 DDL／事务，至少选一种。
- 周视图根据整周未筛选数据压缩共同空闲的连续两小时及以上，区间内部也算占用。当前时间线、滚动和点击使用压缩行的起止时间。
- Home 按日期、今日标签、进行中事务、时钟排列，开始、结束和午夜边界触发刷新。待办统计只计算 DDL。
- 循环沿用阶段二的有限次数规则；区间以结束时间消耗次数。
- 循环拆分保留单次修改与完成、删除历史，修改安排前提供预览；范围日程在后台分批查询，支持取消过期查询。
- 完成、删除支持 10 秒撤销；暂停不顺延、不补发提醒；Home 条目可展开并定位到 Calendar。具体边界规则见 [使用说明](instruct.md)。
- 周视图同时压缩空白时段、展开繁忙时段，按时间顺序单列排列文字，时间写在行内；筛选保持行高和节点位置。全天标签只保留日期和内容，日程点击空白可清除选择，未选中卡片保留悬停效果。见 [本轮界面调整报告](report-calendar-layout.md)。

#### 个人自托管云端

云端只服务当前使用者。客户端在设置中填写云服务器 IP、端口和访问令牌，程序按需连接个人服务器。

第一版云端闭环包含：

- 定时获取天气并缓存。
- 定时轮询 IMAP，保存邮件摘要并标记服务器已读。
- 同步 Calendar、普通纸条、网站书签、排序、共享设置及邮件状态；设备专属设置保留本机。
- 提供手动同步、上次同步时间、失败原因和本地离线状态。

已实现 HTTPS JSON API，客户端保留本地数据及持久化待上传队列，服务器提供定时任务和增量变更。同一记录发生冲突时保留双方内容供选择。服务采用单用户令牌；秘密密库、设备文件书签和设备设置不参与本轮同步。

首批接口：

```text
GET  /health
GET  /v1/changes?cursor=<cursor>
POST /v1/mutate
POST /v1/mail
GET  /v1/weather/{city}?refresh=false
```

#### 模型接口

第一版接入 DeepSeek 或兼容 OpenAI 风格 API，优先处理三个动作：

- 用自然语言创建 Calendar 条目。
- 生成今日事务清单。
- 对已有事务做轻度排序和分组。

模型只输出经过 schema 校验的命令，例如 `create_calendar_item`、`update_calendar_item`、`list_today`。Z.T.L 展示解析后的日期、时间、类型、标签和修改内容，使用者确认后才写入本地或云端。模型不能直接读取密库正文，不能直接删除条目，不能绕过确认执行同步动作。

#### 前端与动效

- 建立统一的颜色、字号、间距、圆角、边框和状态令牌。
- 统一 `PageHeader`、`FilterBar`、`PopupPolicy`、`StatusMessage`、`Card` 等组件。
- Calendar 用颜色区分条目类型，用状态图标表达完成、暂停和重要。
- Note 保留卡片布局，增加拖动插入线、保存状态和锁定反馈。
- Mail 统一未读、收藏、删除、同步和正文加载状态。
- 动效采用 120 到 240 ms 的淡入、位移和高度变化，尊重 Windows 的减少动画设置。
- 用 UI 截图测试检查宽窗口、窄窗口、键盘焦点、弹窗和状态切换。

#### 阶段三交付与验收

- 三种 Calendar 条目可以创建、编辑、筛选、显示和删除。
- 全天标签出现在 Home 和 Calendar，同一天可以显示多条。
- 区间事务限定同日，允许重叠，只显示状态，不触发提醒。
- 个人云端能完成一次天气、邮件和本地数据同步，断网时本地功能继续工作。
- 模型能把自然语言转换成可确认的 Calendar 命令。
- 四个主页面使用同一套视觉组件和动效规则。

## 技术路线

### 技术选型

| 类别 | 选择 | 用途 |
| --- | --- | --- |
| 桌面框架 | Qt 6.11 + C++17 | 窗口、控件、系统托盘、网络和 SQLite 接口 |
| 邮件适配 | Python 3.13 + `imaplib` | IMAP 摘要、正文、已读标记和恢复 |
| 本地数据库 | SQLite | Mail、Calendar 和同步游标 |
| 本地配置 | JSON + `QSettings` | 轻量设置、标签目录和窗口状态 |
| 云端接口 | HTTP JSON | 个人服务器同步和定时任务 |
| 模型接口 | DeepSeek/OpenAI 兼容 REST API | 结构化 Calendar 命令 |
| 测试 | Qt Test + Python 测试 | 数据、业务、UI、邮件和部署验证 |

### 目录和数据边界

生产环境统一从 `QCoreApplication::applicationDirPath()` 计算根目录：

```text
<安装目录>/
├── Z.T.L.exe
├── data/
│   ├── config/
│   ├── database/
│   ├── cache/
│   ├── logs/
│   └── vault.ztlvault
├── runtime/
└── scripts/
```

源码仓库不提交 `data/`、`build/`、`runtime/` 生成文件、邮箱授权码、天气 Key、模型 Key 或云端令牌。生产包可以携带 `runtime/`，Git 仓库只保存准备运行时的脚本。

## 构建和运行

项目使用 Windows、Qt 6.11.0 MinGW 64 位和 Qt 配套工具。构建：

```powershell
.\scripts\build.ps1
.\start.ps1
```

打包：

```powershell
.\scripts\package.ps1
```

当前保留的部署包位于 `build/ZTL-package-recurrence/`，直接运行其中的 `Z.T.L.exe`。打包脚本默认生成 `build/ZTL-package/`，使用 `-Destination` 可指定目录；替换现有包时需保留其 `data/`。

Qt 路径可以通过 `-QtRoot` 或 `QT_ROOT` 指定。开发测试可以设置 `ZTL_DATA_DIR` 使用独立数据目录，生产运行不设置该变量。
