# Z.T.L 个人云端

服务器已独立部署，电脑关机不会停止服务端任务。客户端没有安装或初始化服务器的按钮。

## 首次连接

1. 打开项目中的 `cloud-connection.local.md`，取得地址、端口、访问令牌和证书位置。这个文件仅留在本机，不进入 Git。
2. 打开 Z.T.L → 设置 → Advance，填写云端地址、HTTPS 端口、访问令牌。输入框回车或离开焦点时自动应用。
3. 点击“选择证书”，选择部署提供的 `cloud-server-ca.crt`。程序把证书复制进 exe 旁的 `data/cloud/`，搬动安装目录后仍可使用。
4. 点击“测试连接”，成功后勾选“启用个人云端”，再点击“立即同步”。首次连接会上传本机已有的公开业务记录和邮件任务配置。不同 ID 合并；相同 ID 内容相同直接接续，不同内容保留为冲突。

访问令牌相当于这个私人服务的连接密码，由部署脚本随机生成。它不是 SSH 密码，也不用于安装或管理服务器。客户端只保存连接设置，真实地址和令牌没有写入源码。

没有启用云端时，客户端继续使用原有本地模式。启用后断网仍可编辑，待上传记录保存在 `data/cloud/state.json`，重连自动继续。启动、返回应用、业务修改后及每 30 秒触发数据同步。系统提醒仍由本机执行。

## 同步范围

| 内容 | 行为 |
|---|---|
| Calendar | 完整原始记录，包括循环、单次例外、暂停、完成、删除；全天标签的日期不转换为 UTC |
| Note | 普通纸条、网站书签、标签、排序 |
| 共享设置 | 城市列表与选择、天气 Key、Calendar 与邮件业务设置、邮箱任务账户 |
| 邮件状态 | 摘要读取后，应用内已读、星标、删除及恢复状态跨设备同步；正文按需取得 |
| 本机独有 | 秘密及密库、文件和目录书签、窗口位置、开机启动、连接设置、本地路径、提醒回执 |

不要在多台设备间直接覆盖整个 `data/`，其中有设备本身的配置和独立同步状态。新设备填写连接信息后通过接口同步。

## 邮件与天气

启用云端后，邮箱账户和授权码通过 HTTPS 同步到私人服务器，由服务器定时执行 IMAP。服务器先提交摘要，再将原邮箱标为已读；标记失败会重试。Z.T.L 自己的未读状态独立管理，不随 IMAP 标记而消失。客户端自动收信只读取云端缓存，手动刷新会请求立即轮询。更早摘要、正文、删除恢复按需从原邮箱查询。原邮箱已经删除的正文无法恢复。

轮询设为“不自动同步”时，云端停止定时收信，手动刷新仍可使用。设置变更成功同步后，后台调度最多约 30 秒感知。天气按已保存城市缓存约 20 分钟；手动刷新可立即更新。失败保留旧天气并显示更新时间和原因。

邮箱和天气 Key 沿用现有设置页填写。服务器新部署时没有这些配置，因此未连接客户端前不会收信，也没有真实城市天气缓存。

## 冲突处理

设置页显示冲突数量，点击“处理同步冲突”查看本机和云端版本，选择“保留本机”或“使用云端”。设置类预览不展示邮箱授权码及天气 Key。未选择前，该记录保持暂停；其他记录继续同步。

解决过的双方内容留在本机同步状态的 `resolved` 中。若要组合两个版本，先选保留版本，再通过正常编辑补充另一份内容。共享设置作为一个整体参与冲突判断。

## 服务器目录与维护

服务位于 `/opt/ztl-cloud`：

| 路径 | 内容 |
|---|---|
| `server/.env` | 访问令牌、监听端口、部署镜像配置 |
| `server/data/ztl.sqlite` | 业务记录、修订日志、重试回执、邮件摘要和天气缓存 |
| `server/certs/` | 私有 CA 与服务器证书；CA 私钥只留服务器 |
| `server/backups/` | 每日数据库备份，最多保留 30 份 |
| `/etc/cron.d/ztl-backup` | 每日 03:23 按服务器系统时区备份 |

SSH 进入服务器后，在 `/opt/ztl-cloud` 执行：

```sh
docker-compose --env-file server/.env -f server/compose.yaml ps
docker-compose --env-file server/.env -f server/compose.yaml logs --tail=100 api
docker-compose --env-file server/.env -f server/compose.yaml restart
python3 scripts/cloud_backup.py server/data/ztl.sqlite server/backups
```

Docker 随系统启动，容器采用 `unless-stopped` 策略。日志每个容器最多约 3 × 10 MB。部署脚本重复执行会保留数据库、证书和已有令牌；先构建镜像，再停止并替换容器。

私有 CA 有效期 10 年，服务器证书有效期 825 天。到期前使用原 CA 重新签发含服务器 IP 的证书并重启 HTTPS 容器，客户端继续信任原 CA。更换 IP 时也应重新签发证书。不要关闭证书验证来处理连接错误。

备份是同一磁盘上的恢复副本，不能抵御整块云盘丢失；需要时将备份、`.env` 和证书目录另行下载保存。

## 备份恢复

先停服务并给当前数据库做一份备份；再将选定备份放回 `server/data/ztl.sqlite`，一并移走停机后的旧 `-wal`、`-shm` 文件，再启动。不要在服务运行时直接覆盖 SQLite 文件。

恢复较旧备份可能丢失备份之后的服务端修订。客户端发现修订号倒退或数据集身份变化会停止自动上传，保留本地修改并提示核查。此时保留各设备的 `data/`，人工核对服务器与本机后再重新建立同步基线；不能仅删除 `state.json` 试图绕过提示，否则旧数据可能被当成新增记录。

## 开发验证

在单独 Python 虚拟环境安装 `server/requirements-dev.txt`；Qt 构建沿用现有 CMake。

```powershell
python -m pytest tests/test_cloud_server.py -q
python -m unittest discover -s tests -p test_mail_worker.py
python scripts/test_cloud_integration.py
ctest --test-dir build/Sidekick --output-on-failure
```

HTTPS 联调脚本创建临时证书、令牌和独立测试库，不使用正式服务器数据。测试构建运行时需要 Qt 和 MinGW DLL；脚本默认使用本项目现有的 D 盘 Qt 路径。
