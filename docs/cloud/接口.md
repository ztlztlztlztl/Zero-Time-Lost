# 云端接口协议 v1

所有请求使用 HTTPS，携带 `Authorization: Bearer <token>`。无效令牌返回 401。客户端不接受重定向，也不忽略证书错误。

| 方法与路径 | 用途 |
|---|---|
| `GET /health` | `ok`、协议号、数据集 UUID、最高修订号、后台任务状态 |
| `POST /v1/mutate` | 单条乐观并发修改或删除 |
| `GET /v1/changes?cursor=0&limit=100` | 按修订号升序读取不可变变更；上限 500 |
| `POST /v1/mail` | 缓存摘要、手动轮询、历史摘要、正文、恢复 |
| `GET /v1/weather/{city}?refresh=false` | 六位城市编码，缓存或强制刷新 |

修改请求：

```json
{"op":"unique-operation-id","kind":"calendar","id":"stable-record-id","base":0,"deleted":false,"payload":{"id":"stable-record-id","title":"example"}}
```

`kind` 为 `calendar`、`note`、`order`、`settings` 或 `mailflag`。`base=0` 表示从未见过该记录，否则必须等于服务端当前修订。删除保留墓碑，`payload={}`。修订号为全局递增整数，客户端不得以本地时间排序决定覆盖。

成功返回 `{"ok":true,"record":{kind,id,rev,payload,deleted}}`。修订不符返回 HTTP 200、`{"ok":false,"conflict":{...}}`，客户端保存冲突并等待选择。相同 `op` 和相同请求原样返回原回执，不重复写入；相同 `op` 携带不同内容返回 409。

变更返回 `{dataset,records,cursor,more}`；分页记录是当时的完整快照，不从当前实体表拼接，因此后续修改不会改变旧页面。`cursor` 只在本地应用成功或持久化冲突后前移。游标大于服务端最高修订返回 409。

邮件请求包含 `address`、`command`（`sync/history/body/restore`），以及可选 `cursor`、`validity`、`before`、`id`、`force`。`sync` 默认只读缓存，`force=true` 请求立即 IMAP 轮询。响应沿用本地 Python 适配器 `{ok,data}` 或 `{ok:false,error}`。`data.warning` 表示仍返回缓存，但最近一次轮询失败。

天气返回 `temperature`、`weather`、`updated`、`attempted`、`error`。更新失败时旧成功数据及其 `updated` 保留，不能把失败尝试时间当作新天气时间。
